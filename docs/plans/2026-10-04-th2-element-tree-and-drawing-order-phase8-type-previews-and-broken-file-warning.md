# TH2 Element Tree Phase 8: Type Previews and Broken-File Run Warning — Implementation Plan

- **Date:** 2026-10-04
- **Status:** Proposed; validated against `main` at `e5723be9`.
- **Parent:** [TH2 Element Tree and Drawing Order](2026-09-23-th2-element-tree-and-drawing-order.md), Phase 8.
- **Related:** [TH2 Text Editing Mode](2026-09-25-th2-text-editing.md), especially its later broken-file repair flow.
- **Issue:** [#32](https://github.com/rsevero/mapiah/issues/32).

## 1. Outcome and boundaries

Replace the generic point, line and area images in the `.th2` element tree with small previews of their type and subtype. The previews follow the active visualization method and theme, stay the same at every canvas zoom, and do not depend on the individual element's geometry or options other than subtype. Scrap and non-element rows keep their current icons. Add a warning to the Run Therion dialog listing loaded broken `.th2` files; the warning never prevents the run.

This phase does not create a project-wide TH2 scanner, change Therion diagnostics or make broken files editable. When the [text-editing plan](2026-09-25-th2-text-editing.md) later lets a user repair a broken file in Mapiah, the warning must use the controller's *current* `isBroken` state, so it disappears after a successful repair and can reappear after a reload of broken disk content.

## 2. Verified starting point

- `_TH2ElementRow._buildIcon` in `th2_element_tree_row_widget.dart` selects one of three generic asset paths. The icon is already inside `ExcludeSemantics`, and the row has a separate text semantics label. The row's chevron and icon slots are fixed-width; the replacement must keep the label aligned with scrap rows.
- `TH2ElementTreeAux` builds rows on each call and caches their labels by `structureRevision` and locale. A type or subtype change must invalidate the label cache and rebuild the preview; a preview widget also needs to see visualization-setting and theme changes. `MPSettingsController.getEnumWithDefault` is not itself observable: `setEnum` increments `getTrigger(MPSettingID.TH2Edit_VisualizationMethod)`.
- `MPVisualController.getDefaultPointPaint(THPoint)` reads the point's subtype and other options, uses the controller's zoom for stroke width, and modifies a `Paint` while preparing it. Its label fallback can resolve an element's own text. `getDefaultLinePaintByTypeSubtype` also mutates a shared primary paint while resolving its stroke width. Copying either getter's result afterward is too late to prevent that mutation; a detached point proxy does not prevent it either.
- `getDefaultLinePaintByTypeSubtype`, `getLineDecorator`, `getLineDecoratorColor` and `getDefaultAreaPaint` resolve the active Therion style. The area resolver obtains a pattern tile through `MPPatternCache`; its tile builder is synchronous. Its shader scale currently uses the file controller's canvas scale, so copying the resulting paint alone would leave the preview zoom-dependent.
- `THLinePainter.paint` mixes path construction, marks, direction ticks, base stroke or fill, dashes and decoration. Its dashed path lengths use `scaleScreenToCanvas`. The reusable path-painting part needs explicit preview scale and decorator inputs, including the sample vertices and segments decorators consume. It and `MPInteractionAux.drawPoint` widen each highlight-border `Paint` in place (`highlightBorder..strokeWidth = …`) while drawing.
- `TH2FileEditController.transformCanvas` ends with `canvas.scale(1, -1)`, so element painting runs on a Y-up canvas. `MPInteractionAux.drawPoint` and `MPLabelPainter` cancel that reflection locally, and area patterns are oriented for it; drawing them on an unflipped canvas renders symbols, labels and patterns upside down.
- The canvas interior color is not a theme color: `th2_file_widget.dart` picks `Colors.black` or `Colors.white` inline from `Theme.of(context).brightness`.
- `MPSymbolUnit.canvasValue` reads `TH2Edit_SymbolUnit` even when canvas scale is fixed. Its separate `oneMeterInLocalUnits` depends on scrap scale and is used by the SKBB handrail point symbol. Preview construction must supply both effective values explicitly to avoid settings and active-scrap dependencies.
- `MPGeneralController` holds registered `.th2` controllers in `_t2hFileEditControllers`, including loaded controllers without tabs. `MPRunTherionDialogWidget.initState` starts Therion immediately. Its output lives in a fixed-height `AlertDialog`, so the warning must not consume unbounded height.

## 3. Preview data and paint resolution

1. Add a value object for the preview key: element kind, type, normalized subtype, visualization method, device pixel ratio, every theme color painted into the picture (including `colorScheme.outline` and the icon's interior background color), and any effective symbol-set choice not already fixed by the visualization method. Include brightness only if it affects rendering beyond those colors. Do not include MPID, controller identity, file path, selection, actual geometry, `-orient`, `-scale`, `-reverse`, `-clip`, `-visibility` or `-id`. Use one representation for missing subtype (`mpNoSubtypeID`).
2. Resolve each preview through the row's registered, valid file controller, which is available for expanded tab-less files too. For points, make a type/subtype-only paint-resolution path (or a minimal detached proxy) so label-mode types use `mapiahPlaceholder` and cannot render an element's text. Force neutral orientation and the preview radius. Reuse the normal symbol registry and default paints for other point types.
3. Make point and line preview resolution copy shared paints before any stroke-width assignment or other mutation. Use a preview-specific resolution path or refactor the existing getters to copy before mutation while preserving canvas rendering. A minimal detached point proxy is sufficient only when its resolver also follows this rule. Copying the results of the current mutating getters is insufficient. Copy every `Paint` and paint list that preview rendering will adjust: border, fill, primary and secondary strokes, decorator color and highlight borders. `THPointPaint.copyWith` and `THLinePaint.copyWith` create new paint containers, but retain the original `Paint` objects and `highlightBorders` list unless replacements are passed explicitly. Copy the list and its mutable `Paint` entries before adjusting them. Preview paints come from the default getters, never from `getUnselected*Paint`, so they carry no highlight borders; the extracted painter's in-place highlight widening therefore never touches a preview paint. Set preview stroke widths only on copies. Do not mutate the visual controller's cached/default paints or the paint objects used by a canvas already on screen.
4. Give area-pattern resolution the explicit preview `MPSymbolUnit` from item 5 so its image shader is based on the fixed icon scale. Continue to use the file visual controller's `MPPatternCache` for the tile image; tile construction is synchronous, so no pending-image fallback or repaint subscription is needed. Retain the canvas method's current scale as its default. Test a patterned area at two canvas zooms.
5. Add a preview construction path to `MPSymbolUnit` that accepts positive effective `canvasValue` and `oneMeterInLocalUnits` values directly, without reading `TH2Edit_SymbolUnit`, canvas zoom or the active scrap. Define both values in `mp_constants.dart` and choose them to keep symbols, including the SKBB handrail stem, readable within the icon. Pass the same fixed preview unit to point symbols, line decorators and area-pattern resolution. Retain the existing settings- and scrap-derived construction path for canvas painting, with unchanged behavior.

## 4. Shared path painting and icon layout

1. Extract from `THLinePainter` the path-painting operation after its path and vertices have been assembled. It takes the canvas, path, vertices or sample segments required by the decorator, `THLinePaint`, decorator and decorator color, an explicit `MPSymbolUnit`, explicit line thickness, explicit dash scale, and an explicit cleaning background color for `cleanBeforeFill`. Preserve `THPaint.thPaintWhiteBackground.color` as the canvas default; the icon passes its own interior background color so patterned previews in dark mode do not clean to white. Pass the decorator's existing flags (`isReversed`, border and arrow choices) explicitly; the icon supplies neutral values and no line-direction ticks. `THLinePainter` calls the helper with its current controller-derived values, preserving canvas output. The helper keeps the existing in-place highlight-border widening only to preserve canvas output; do not extend that mutation to other paints. Keep mark and line-point painting in `THLinePainter`. Preserve the existing painting order, including direction ticks between the base stroke or fill and decoration; split the reusable operation into passes if needed.
2. Create `TH2ElementTypeIconPainter` and `TH2ElementTypeIconWidget`. Point symbols sit on the preview background without a frame. Line and area previews use the same small outline frame: the line normally has a fixed cubic S-curve, with the SKBB `steps` exception defined in item 4, and the area has a fixed closed oval. Use `colorScheme.outline` for the frame and the canvas background color for the inside. Extract that color from `th2_file_widget.dart` into one shared helper (brightness → black or white) used by both the canvas container and the icon, so they cannot drift; the icon's key then carries it through §3 item 1's interior background color. Before painting element content, apply the same reflection as `transformCanvas`: translate to the icon center and `scale(1, -1)`, and define the sample S-curve, oval and point position in that Y-up space, so `drawPoint`, `MPLabelPainter` and area patterns cancel or rely on it exactly as on the canvas. The frame is drawn outside the reflection. Clip content to the icon box; choose a sample length and symbol unit that leave visible room for long decorators and line caps.
3. Put icon dimensions, frame thickness, padding, sample geometry, effective preview symbol-unit value, preview one-meter drawing length, line thickness, point radius and cache limit in `mp_constants.dart`. Keep the icon within `mpProjectTreeRowHeight`. Replace `_TH2ElementRow._buildIcon` only for point, line and area rows; leave the scrap icon and row semantics intact.
4. Feed decorators stable synthetic geometry and metadata rather than a real row element, with a fixed synthetic MPID for procedural randomness. Select the sample from the resolved decorator, since the same line type can resolve differently across visualization methods. Add the subdivision count, rail geometry and slope tick length to `mp_constants.dart`. These existing SKBB contracts require explicit samples:

   - `MPStepsSKBBLineDecorator` needs at least four segments and an even segment count; a two-point cubic instead draws its invalid-definition red stroke. Use five synthetic straight-line points: an initial discarded point, then the left and right ends of the upper rail, followed by the right and left ends of the lower rail. Build the sample path from those same points. This gives the decorator two horizontal rails and two end rungs inside the frame. This is the defined exception to the generic S-curve; keep the default arrow and border choices and do not change the canvas decorator.
   - `MPFixedLadderSKBBLineDecorator` builds its rails from segment knots, while its rungs follow the curve. Subdivide the fixed S-curve into eight cubic segments with matching control points and endpoints, preserving the exact curve while supplying nine distributed knots. Pass those segments and their vertices together so the rails follow the sample instead of the straight chord between its endpoints.
   - `MPLineSlopeSKBBLineDecorator` defaults missing endpoint `l-size` to `mpSlopeLinePointDefaultLSize` (40 drawing units), which exceeds the 28-pixel tree row. Supply an explicit fixed preview `lSize` on every synthetic segment, sized to fit the frame's inner height with room for the curve and stroke. Leave `orientation` unset for perpendicular ticks, `isReversed` false and `showBorder` false. This metadata belongs only to the synthetic preview and never reads or changes the element's options or the canvas default.

   Check the remaining decorator contracts before extraction. If another decorator cannot produce a representative preview from its synthetic sample, define a neutral fallback and cover that type in a test. Returning without drawing or drawing an invalid-definition diagnostic also counts as an unsuitable sample; do not rely only on detecting exceptions.

## 5. Cache and invalidation

- Cache the rendered `ui.Picture` by the value key from §3, with a bounded least-recently-used policy. The cache exclusively owns its pictures and exposes a synchronous draw operation taking the destination canvas, key and recording inputs; it never returns a picture to a widget or painter. That operation looks up or records the picture, updates recency and draws it before returning. Widgets and painter delegates retain keys and rendering inputs only, so a later repaint looks up the key again and recreates an evicted entry. No raw picture reference survives outside the cache. Dispose a picture exactly once when evicting or clearing it, after any synchronous draw using it has returned. Keep the cache owner at app scope or another scope that survives row recycling. On app teardown, unmount its consumers and dispose its setting reaction before clearing pictures and disposing the owner; reject use after disposal. Cache creation is lazy, when a visible icon paints.
- The widget observes `structureRevision` for the file's element type/subtype changes and `getTrigger(MPSettingID.TH2Edit_VisualizationMethod)` for visualization changes. Theme colors and device pixel ratio come from build context and participate in the key. On a visualization-setting change, clear old entries as well as rebuilding visible rows; a key change alone leaves unused pictures resident.
- The cache shares pictures only when type, subtype and effective rendering inputs match. If any resolved paint can vary by file settings beyond that key, add that setting to the key or remove the file dependency by using a fixed preview value. Canvas zoom must never enter the key or picture content. The preview symbol-unit and one-meter values are fixed constants, so `TH2Edit_SymbolUnit` and active-scrap scale are neither cache-key inputs nor invalidation triggers.
- Verify the subtype update path actually bumps `structureRevision` for set, unset, undo and redo. If a path does not, fix that invalidation in this phase instead of forcing the entire tree to rebuild.

## 6. Run Therion warning

1. Add a read-only `MPGeneralController` getter returning a sorted snapshot of filenames for registered controllers with `isFileLoaded && isBroken` and no `loadError`. Include controllers opened only by expanding a project-tree file row and standalone loaded controllers. Do not load extra files to populate the list. Controller rename/removal naturally changes a later snapshot.
2. Snapshot that getter when `MPRunTherionDialogWidget` opens. Show a localized plural-aware warning and the file paths above the output pane. Use a bounded scrollable list or bounded warning region so a large number of paths leaves output and run controls usable. Paths are selectable plain text, not links. The injected-runner test path must use the same widget behavior.
3. Preserve the current `initState` run start and rerun behavior; no wait, confirmation or cancellation is added. The warning states that Therion *may* fail, since the run itself determines the outcome. A dialog already open keeps its opening snapshot; a newly opened dialog reflects a file fixed by the later text-editing flow.

## 8. Implementation and verification sequence

1. First add focused tests for the preview key, zoom independence, mutable-paint isolation (including the `highlightBorders` list and its entries) and the broken-controller getter. Capture shared paint state before preview resolution and verify it remains unchanged after resolution and rendering, including when canvas zoom differs from the preview scale. Confirm `t3952` remains free before naming the icon suite `t3952_th2_element_type_icon_test.dart`; otherwise take the next unused prefix. Extend `t3610_ui_therion_run_dialog_test.dart` for warning display and run continuity.
2. Before extraction, add baseline canvas goldens that invoke `THLinePainter` itself with controller-resolved paints and representative segment data. Cover continuous strokes, dashes, decoration, patterned fills with `cleanBeforeFill`, and direction ticks overlapping decoration so painting-order changes are detectable. Capture these baselines from the existing painter, then refactor the paint core with explicit scale and cleaning-background inputs and require the baselines to pass unchanged before adding preview rendering. Also run `t3764`–`t3766`; their decorator and pattern-tile goldens remain useful but bypass `THLinePainter`, so they do not establish canvas-painter equivalence.
3. Add icon rendering, cache and row integration. Golden cases in light and dark themes, under placeholder and at least one Therion mode: symbol point, label-mode fallback, continuous line, decorated line, solid area and patterned area, including a pattern that requires `cleanBeforeFill` to verify the preview background in both themes. Include a vertically asymmetric point symbol and a label-mode fallback so an orientation error in the icon's reflection is visible. Test type/subtype edits with undo and redo, visualization changes, brightness changes and two color schemes with the same brightness, identical icons for elements with different unrelated options or geometry, one cache entry for the identical type keys, and stable output across zoom levels and tab-less controllers. Change `TH2Edit_SymbolUnit`, switch active scraps, and render through controllers with different scrap scales; verify identical preview output and cache reuse, including the SKBB handrail point and a patterned area. Check scrap icon, alignment and semantics.

   Add light/dark SKBB goldens specifically for `steps`, `fixed-ladder` and `slope`: verify the steps sample renders rails and rungs instead of the red invalid-definition stroke, fixed-ladder rails follow the distributed curve knots, and slope ticks fit inside the frame without relying on clipping their full-length ends. Assert the sample segment counts, matching path/segment geometry and explicit slope `lSize` values. Use the same cases for zoom, scrap-scale and unrelated-option independence.

   Exercise cache lifetime with a deliberately small limit: keep an icon mounted, evict its entry by painting other keys, then force it to repaint without rebuilding its delegate. Repeat after clearing the cache while the icon is mounted, and after a visualization change. Verify recreation, correct output, no disposed-picture use, exactly-once disposal and the cache limit throughout. Unmount consumers and dispose the owner, verifying all remaining pictures and the setting reaction are released and later use is rejected.

4. Add the warning getter and dialog UI. Test zero broken files, one tab-less broken file, multiple sorted paths, valid and load-error controllers excluded, long-list layout, and an injected runner starting and finishing with the warning visible. Test a second dialog after a controller changes from broken to valid.
5. Update EN/PT ARB, generated localizations, both help pages and CHANGELOG. Run focused tests, then `flutter analyze` and `flutter test` in the task worktree. Inspect the diff for unrelated paint, output or tree changes.

## 9. Acceptance criteria and risks

- Every loaded point, line and area tree row shows a readable type preview with a fixed footprint. Type and subtype changes, undo/redo, visualization changes and theme changes refresh it. Zoom, the symbol-size setting, active-scrap changes, scrap scale, unrelated options, selection and individual geometry do not.
- Canvas painting and existing golden output are unchanged. Preview rendering does not alter shared paints, retain or draw disposed pictures, leak pictures or grow the cache beyond its limit. Mounted icons repaint safely after eviction or clearing. SKBB steps, fixed-ladder and slope previews use the explicit samples in §4 and remain readable within the frame.
- Run Therion starts exactly as before. The warning lists only currently loaded broken `.th2` files in deterministic order and does not mistake a load error for a parsed broken file.
- EN/PT help and localization describe the actual behavior, and the full analysis and test gates pass.

The main implementation risk is that a line decorator expects real segment metadata or uses controller scale internally. Resolve those dependencies explicitly in the shared painter interface and cover representative decorators in goldens. The second risk is shared mutable `Paint`: copy it before any mutation during preview resolution or rendering, and verify the canvas paints and painter integration goldens after preview rendering.
