## 3. Shared editor contracts

Add `THTextEditorBuffer` as an abstract interface, with `THTextEditorLanguage { therion, th2 }`. Use the existing member signatures where possible:

| Highlighting | `List<THTextEditorToken> get tokens`, implemented as a `@computed` of `content` in both controllers (§4) |
| Cursor/navigation | `cursorLine`, `setCursorPosition`, `pendingScrollToLine`, `clearPendingScrollToLine`, `pendingSelectionRange`, `pendingSelectionRequestsFocus`, `clearPendingSelectionRange`, `double lastScrollOffset` (read/write: the main field's initial offset and the scroll listener's target, §5.1) |

Its language is `therion`, line ending is LF, `canSave == isDirty`, `isReadOnly == false`, `revertTooltip == null`, `baselineRevision == 0`, and `hasTextEdits == true`. Ignore the new optional cursor offset there. Its `setContent` returns `false` where it already rejects a change (`registerTextContentChange` returning `-1`), and `true` otherwise. Its fold members (`foldRegions`, `collapsedFoldStarts`, `toggleFold`) stay on the controller and out of the interface, since no widget reads them. It gains its own `textFieldFocusNode`, disposed with `textEditorFocusNode`. Its `lastScrollOffset` stays 0 and ignores writes, so project tabs keep their current scroll behavior.

Add optional `leadingToolbarActions` to `THTextEditorWidget`, before the ordinary toolbar actions. Phase 4 supplies the Canvas button. Save follows `canSave`; Revert preserves the project behavior and uses the TH2 discard tooltip for TH2. For TH2, Revert is enabled while `isDirty` and not `isReadOnly`. Await Revert through an error-handling handler.

### 3.2 Shared find logic

Pass the end of the replaced range in the new text: the single replacement's end, or the last replacement's end for Replace All (§4.14). Replacement actions check the buffer's `isReadOnly`, including direct controller calls, and the widget disables the Replace and Replace All buttons while `isReadOnly`. Find query edits and navigation remain allowed while the main buffer is locked.

Regenerate MobX files in the worktree after changing annotated stores. Verify in an `Observer` that the find store's observables and `findMatches` follow both query changes and buffer content changes.

## 4. TH2 lexical behavior

Keep the default `tokenizeTherionText(text, language: therion)` and default `buildFoldRegions(content, language: therion)` compatible with current callers. Choose TH2 block openers for auto-indent through the same language selection.

For TH2:

1. Recognize `encoding`, `scrap`, `endscrap`, `point`, `line`, `endline`, `area`, `endarea`, `comment` and `endcomment` as keywords. Color strings and bracket values, signed numbers, station references, inline comments and dash options, as §4.7 defines them. In TH2, only `"…"` and `[…]` are values; `'` is plain text. Color these as keywords only as the whole first word of a logical line, case-insensitively as the grammar's `stringIgnoreCase`, the only place the grammar reads them as commands; elsewhere, as in `-context point anchor` or a `u:point` type, they are plain. Two of them have narrower places: `encoding` is a keyword only on the file's first non-blank logical line, since the parser rejects it anywhere else; `comment` opens a block (keyword, fold and comment body) only when nothing but whitespace or an inline `#` comment follows it, since the parser rejects `comment foo` and opens no block there.
2. As the first word of a logical line at file level (leading whitespace allowed, case-insensitive, as the grammar's `stringIgnoreCase(…).trim()`), classify `##XTHERION##` and `##MAPIAH##` settings as `setting`, before ordinary hash-comment handling. As in the grammar's `xtherionConfig`/`mapiahConfig`, the line is a setting when the prefix is followed, after optional whitespace, by a keyword starting with a letter, digit, `_` or `/`, and then, after optional whitespace, by at least one more character. No whitespace is needed after the prefix: `##XTHERION##xth_me_area_adjust 0 0 1 1` is a setting. Otherwise the parser reads the line as a comment, so color it as `comment`: `##XTHERION##` alone, `##XTHERION## xth_me_area_adjust` with nothing after the keyword, and `##XTHERION## !foo`. Inside a `scrap`, `line` or `area` block the parser reads such a line as a comment (parent §2.3), so color it as `comment` there. Add `setting` to `THTextEditorTokenType` and one setting color to the editor's existing palette, which is a single fixed palette: neither the editor nor the app has a dark theme (`main.dart` has `darkTheme` commented out).
3. Carry block context across lines. Inside a `line` block, a logical line starting with one of the words of the grammar's `lineSegmentOptions` (parent §4.10, including `l-size`, `orient`, `head`, `text` and `scale`) starts with an option; inside an `area` block, the same holds for the words of `areaCommandLikeOptions` (`clip`, `context`, `id`, `place`, `visibility`). Match the whole whitespace-delimited first word, case-insensitively, so `l-size` is one option word rather than `l` followed by a dash option. Do not classify coordinates, quoted text, a border reference or the same word elsewhere by that rule. An option word glued to its argument, such as `size3`, which the grammar accepts, stays plain: a single-word coloring deviation, stated so it isn't mistaken for a bug. Block context follows explicit closers only. The parser's recovery that implicitly closes an unterminated `line` or `area` at a following structural command (`point`, `line`, `area`, `scrap`, `endscrap`, and `endline` in an area) isn't modeled: in that already-invalid text, option words after it may still be colored as options, and the existing fold rule, where a closer pops to its matching opener, already drops the unclosed block's fold.
4. Between `comment` and `endcomment`, treat body text as comment, including apparent commands and settings. The fold scanner must ignore apparent block openers and closers in that body. Recognize the actual closing command as the parser does: a body logical line whose text, after leading whitespace, starts case-insensitively with `endcomment` closes the block, whatever follows (`endcomment foo`, `endcommentx`, `endcomment"x"`), since the comment-body grammar doesn't require the end of the line. A word inside a string or an inline comment, or after the start of the logical line, never ends the block. Lines that change structure or whole-line color follow the parser, including such glued forms. As the grammar's `commandTemplate` accepts an end-of-line comment right after the command word, `comment` or `endcomment` directly followed by `#` (`comment#c`, `endcomment#x`) is the command plus an inline comment: it opens or closes the block, as the parser does. `endline#c` and `endscrap#c` are rejected by the parser and need no such rule. A body line ending in `\` joins the next line, so an `endcomment` there doesn't close the block (§4.7).
5. Compute fold regions for balanced `scrap`, `line`, `area` and `comment` blocks with zero-based inclusive ranges, as `buildFoldRegions(content, language: th2)`. They are computed regions only: no editor renders folds yet (§2). Preserve the existing tolerant handling of incomplete input; an unmatched opener produces no complete fold. Never require a successful parse to highlight or compute folds for typed text.
6. Ignore the trailing CR of a CRLF line for lexical decisions, without rewriting the source or changing absolute token offsets. Keep line numbers and offsets correct for mixed endings and an unterminated last line.
7. Follow the parser's line splitting (§2). A trailing `\` continues the logical line wherever it appears; the next physical line keeps the token state the `\` left: inside a `#` comment it stays comment, inside an open `"` or `[` value it stays that value, and otherwise numbers, dash options, strings and inline `#` comments keep their normal classifications. For example, a wrapped point command can continue with `-text "label" # note`, keeping option, string and comment tokens. Since the parser joins the next line with no separator, when no whitespace precedes the `\` the next physical line continues the same word: `ab\` followed by `#c` is the word `ab#c`, so a `#`, `"` or `[` at the continuation's start is part of that word. Within a logical line, a `#` at the start of a word outside a value colors the rest of the logical line as comment, so a `"` or `[` after it opens nothing; a `#`, `"` or `[` inside a word is part of it. `"` and `[` open a value only at the start of a word; `""` escapes a quote and brackets nest. Likewise, a dash option and a signed number start only at the start of a word, so `-align bottom-left` keeps `bottom-left` as one plain word instead of coloring `-left` as an option. Outside values and comments, each word gets one classification. A dash option is the whole word, from a `-` followed by a letter to the next whitespace, so `-station-names` is one option. A word is a number only when the whole word matches the grammar's `number()`: an optional `-` or `+` sign, digits and an optional fraction, with no exponent; `2024.01.02` and `3rd` are plain. A whole word matching the project's station-reference pattern, such as `1@cave`, is `stationReference`. `"…"` and `[…]` values are colored as `string`. TH2 has no punctuation tokens: `[` and `]` delimit values, and other characters, such as the `:` of `u:point`, stay in their word. A value still open at the end of a logical line ends there, so the next physical line starts fresh, as in the parser. No continuation line starts a new command, block opener or closer for folds, or `line`-block option line.

Use bounded scans based on input length; no general line diff or lossy large-file fallback. Keep lexical state local to one scan, so tokenizing another buffer cannot inherit it. Expose the tokens of each buffer as a `@computed` of its `content` (the project controller included), so rebuilds that don't change the text, such as cursor moves and find navigation, don't tokenize again; the widget reads `buffer.tokens` through the shared contract instead of calling the tokenizer in `build`. Build the overlay spans in one merged pass over tokens and find matches, instead of scanning every match for every token (§2), in a pure top-level function of the highlighter file rather than a private widget method, so `t3972` can time it without a widget.

## 5. TH2 text-session controller

Add MobX `TH2TextEditController`, owned by one `TH2FileEditController`, implementing both `THTextEditorBuffer` and Phase 2's `TH2TextApplySession`.

### 5.1 State and lifecycle

Store the open session's current and initial text, initial writer map, cursor/column, pending scroll/selection, diagnostics, validation cache and line tracker, plus the last main-field scroll offset (`lastScrollOffset`, plain, not observable), written by the widget's scroll listener. The file's `lineEnding` is the Enter default. Keep session identity (`sessionRevision`) distinct from buffer edits. Installing a baseline advances both `sessionRevision` and `baselineRevision` and resets the edit generation (§5.2), since `applyTextContent`'s staleness check and idle publishing both compare `sessionRevision`; `endSession()` advances only `sessionRevision`. `baselineRevision` drives native history reset.

- Install a prepared baseline atomically: initialize text, map, tracker, diagnostics, find matches and cursor before publishing its new session/baseline revision. Session preparation must not partially overwrite the live session. Phase 4 owns the operation and its recovery policy.
- `isDirty` is true only while a session is open and `content != initialContent`. `hasTextEdits` becomes true on the first actual text mutation and stays true even when undo restores the initial text. Selection changes do not set it.
- `setContent` ignores identical text and refuses mutations while closed, disposed or locked, returning `false`. Otherwise it records the old/new text with the supplied cursor offset, sets `hasTextEdits`, updates find state, invalidates displayed stale feedback, schedules validation and returns `true`. It changes no live model or canvas history.
- `endSession()` cancels the idle timer, advances session identity, clears content/baseline/map/diagnostics/cache/tracker and edit flags, and clears pending navigation and session find state. Keep only the last scroll position for re-entry, as parent §4.6 requires. A baseline replacement preserves find-bar UI/query state as parent §4.15 requires; do not confuse replacement with a complete mode exit.
- Lock ownership belongs to the enclosing owner operation, through the owner's lock (§5.3). The lock is a flag held by that operation, not a counter: `applyTextContent` calls `lockBuffer()` only on an accepted result, and Discard takes it itself, while every operation releases it unconditionally in its `finally` (parent §4.6), even when a rejected or cancelled apply took nothing. Taking it again while held changes nothing, and releasing it when not held is a no-op. `lockBuffer()` acquires it there; only the owner operation releases it, and `endSession()` and baseline installation never do. Internal baseline installation is a distinct authorized path, not a public mutation that bypasses the guard. Expose permanent recovery read-only state separately from a temporary operation lock.
- Dispose timers, cache references and both focus nodes; late completions cannot install diagnostics or revive a closed session. The owner wires tab close/disposal in Phase 4.

### 5.2 Idle validation

Debounce current-buffer validation with `mpTH2TextValidationIdleMilliseconds`, a new constant in `mp_constants.dart` set to 500, regardless of cursor movement. Use the session's existing `TH2TextValidationCache.validate`, with the owner's filename, file MPID and default ending. Keep its exact-content caching and in-flight sharing with `applyTextContent`.

Capture a session revision and an edit generation when starting idle work. Publish only if the owner/controller is still live, the same session is open, the generation is current and the result describes the exact current content. Generation checks prevent an older result from being installed after editing away from and back to the same string. Cache completion alone is not authority to publish UI diagnostics.

Phase 2 already turns lone CR, encoding failures, parse problems and thrown parses into results. Consume those results; do not reimplement validation. Information records describe the current raw source before apply. An unexpected asynchronous failure is logged and surfaced, with no unhandled future error or silent timer failure.

### 5.3 Owner interface

`TH2TextEditController` takes its owner through one narrow, permanent interface, `TH2TextEditOwner`, instead of temporary hooks that Phase 4 would replace. Phase 4's `TH2FileEditController` implements it, so no second operation coordinator is introduced. It provides:

- the validation inputs: filename, file MPID, default line ending and `isDisposed`;
- observable `canSave`;
- the operation-owned buffer lock: observable `isBufferLocked`, `acquireBufferLock()` and `releaseBufferLock()`, both idempotent; only an owner operation releases it, unconditionally at its end, whether or not it was acquired (§5.1);
- `Future<void> save()`, `Future<void> discardTextEdits()` and `Future<void> requestCanvasHistory({required bool redo})`.

The controller's `isReadOnly` is `owner.isBufferLocked` or the recovery read-only state; `lockBuffer()` acquires the owner's lock. Its `canSave` is `owner.canSave`, and false in the recovery read-only state (parent §4.17). The widget reads these inside its `Observer`, so they must be MobX observables, or `TextField.readOnly` and the Save and Revert buttons wouldn't follow them; the fake owner backs them with `Observable<bool>`.

In Phase 3 no production code implements the interface, so no TH2 editor is installed into production tabs. Tests implement a fake owner, recording or throwing, to verify routing, locking and error handling without writing disk or traversing the live stack; a fake with `canSave` false checks that Save stays disabled, and unavailable operations are explicit refusals, never successful no-op saves. The controller's Save checks `owner.canSave`, awaits `owner.save()` and logs failure; Discard awaits the gated owner operation; canvas history requests await the gated owner traversal. No direct call to Phase 2's apply belongs in the widget.

## 6. Widget input, focus and history

### 6.1 Focus and selection

Pass `textFieldFocusNode` to the main `TextField`; retain the wrapper node for Tab/Esc propagation. Update existing project-text tab focus sites in `MPGeneralController` and `TH2FileTabsPage`, and pending selection application, to request the actual field node. TH2 tab activation is Phase 4 work.

Give the main field `InputDecoration.collapsed(hintText: …)`, so its text starts where the overlay, markers and gutter do (§2); the scroll math of pending navigation and active-match navigation already assumes this. Any visual margin goes outside the gutter and field together, so they move as one. This is an intended visible fix for project editors too. Drive the syntax overlay and the diagnostic background from the main field's scroll offset, like the gutter, so colors and markers stay on their lines while scrolling, after find and pending navigation, and after the baseline remount (§6.3). Create the main field's scroll controller at `lastScrollOffset` and write the offset back from its listener.

Add `pendingSelectionRequestsFocus`, defaulting to true and cleared with the pending range. A false value moves selection without taking focus, for later tree context-menu navigation. Pass valid `TextEditingValue.selection.extentOffset` to `setContent`; pass null for an invalid selection.

**A refused change restores the field.** The lock is taken synchronously at accepted apply, but `TextField.readOnly` only follows it on the next frame, so a key event in between can still change the field. When the listener runs, the field already holds the refused value, so the widget keeps the last `TextEditingValue` it accepted or synced from the buffer. When `setContent` returns `false`, the widget puts that value back into its `TextEditingController` under `_isSyncingFromController`, so the restore isn't reported as an edit and doesn't set `hasTextEdits`. Without it, no observable changes and the build-time resync never runs, leaving the field showing text the buffer doesn't have. This also applies to project editors, whose `setContent` refuses a change after the project moved to a newer epoch or root: that is an intended visible change, since their field previously kept the refused text.

### 6.2 Enter and line endings

For TH2 only, add a second `Shortcuts`/`Actions` pair wrapping the main editor's wrapper `Focus` (gutter and field), as parent §4.15 specifies; the widget has only the outer pair today (§2). Bind Enter, Shift+Enter, numpad Enter and numpad Shift+Enter, including repeats, in it. Replace the selected range with the file's default LF or CRLF and computed auto-indent in one value update. Compute indentation from the preceding text with a trailing CR removed. Place the caret after the full ending and indentation; do not expose a caret position between CR and LF.

Respect active IME composition: Enter used to confirm composition must not also insert a newline. Key events can reach `Shortcuts` before the input method sees them, so while the field's `value.composing` is a valid, non-collapsed range, the Enter action is disabled (`isEnabled` false): `Shortcuts` then neither invokes it nor handles the key, which reaches the input method. A `consumesKey` of false would not be enough, since `Shortcuts` invokes an enabled action before consulting it. Otherwise the action is enabled and consumes the key. Verify this with text-input composition events during implementation. Preserve native CRLF navigation behavior where available; add a narrowly scoped correction only if tests show the caret can land inside an ending, without normalizing the buffer.

Disable the listener's LF-insertion heuristic for TH2. Pasted LF, pasted CRLF and programmatic replacements retain their own endings and get no inferred auto-indent. Keep the project's current LF/auto-indent behavior. Find/replace fields stay outside these shortcuts, so their Enter behavior is unchanged.

### 6.3 Native undo routing

Pass a widget-owned `UndoHistoryController` to the main field. Wrap only that field in a `KeyedSubtree` keyed by `baselineRevision`, retaining the field's fixed key. Reset the associated native undo state when the baseline changes; do not reuse stale history entries. Keep the rest of the widget mounted so find text, replace expansion and focus survive. The remount resets the field's scroll position: its new `Scrollable` starts at the controller's initial offset, since `PageStorage` keeps offsets only under a `PageStorageKey`. Record the offset before the remount. In a build that changes `baselineRevision`, apply nothing to the scroll controller: until the end of that frame the outgoing field's position is still attached and the new one has no dimensions, so a pending selection or scroll applied in that build, as the widget does today, would move the outgoing field. Phase 4 installs a baseline together with a mapped cursor (parent §4.15, §4.17), so this case is real. In one post-frame callback, apply a pending selection, else a pending scroll, else the recorded offset, clamped, and keep the gutter and overlay in sync. Flutter doesn't promise that focus stays on `textFieldFocusNode` while its field unmounts and remounts, so also record whether the field had focus before the remount and request it again in the same post-frame callback, unless a pending selection with `pendingSelectionRequestsFocus` false applies. Install the baseline before user input resumes and never record it as an edit.

Add TH2 undo/redo intents and actions to the same inner shortcuts as Enter, covering the main field and gutter but excluding find/replace fields. Override Flutter's standard `UndoTextIntent` and `RedoTextIntent` actions in an `Actions` wrapping only the main `TextField`, inside that pair: `UndoHistory` exposes overridable actions for them. Route both the custom shortcut intents and standard intents through one history handler, so direct standard-intent dispatch cannot bypass the TH2 guard. With text history selected, invoke the widget-owned `UndoHistoryController` directly; redispatching a standard intent would recurse through the override. Install these overrides only for TH2. Handle Ctrl and Cmd with Shift+Z redo, exactly once:

- When read-only, consume the key and do nothing.
- With `hasTextEdits`, invoke the main field's native undo/redo controller.
- Before the first text edit, request canvas history through the buffer hook, which Phase 4 will gate and recheck. Do not traverse the stack in the widget.

Actions remain enabled and consume the key even for an empty stack, a broken raw baseline or recovery; otherwise default Flutter shortcuts could fall through to native text undo. After a text edit, exhausting text history never reaches canvas history. Project editors retain their existing shortcut behavior; find and replace fields always retain their own native histories.

Every mutating route, including Tab indentation, cut/paste, Replace, Replace All, Enter and programmatic controller edits, observes read-only state. Selection, scrolling, finding and Copy remain usable. Handle exceptions from asynchronous canvas history requests without an unhandled future error.

## 9. Acceptance and risks

- Existing project editor behavior and regressions pass, with typing focus corrected.
- TH2 highlighting and fold regions work on invalid intermediate text and follow the parser's line splitting, with exact source offsets and endings preserved. No fold UI is added.
- TH2 edits update session dirty state, tracking, find state and current diagnostics without changing the model or canvas history.
- Enter is distinguished from paste; diagnostic messages are never overwritten by another marker on the same line; the gutter follows severity and line-less diagnostics are visible.
- Native text undo and canvas requests are mutually exclusive; locked/no-op actions consume keys; find/replace fields keep their own undo.
- Session replacement resets native history, retains find-bar state and never releases the operation-owned lock. Closed/disposed sessions cannot publish late validation.
- Analyzer and full test suite pass after implementation. No TH2 Save is exposed before Phase 4's apply/write pipeline exists.

Primary implementation risks are the find store's tracking of the buffer's content, rebinding native undo state when only the main field is rebuilt, IME-aware Enter dispatch, restoring the scroll offset across the baseline remount, keeping the overlay and markers on the field's scroll, keeping the field and buffer equal when a change is refused, and incompatible diagnostic consumers. Test those seams directly. `TH2TextEditOwner` is a permanent narrow boundary that Phase 4's owner implements, not a second history/gate implementation. The native initial-snapshot limitation remains documented for Phase 7.
