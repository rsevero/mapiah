# Therion Project Parsing Phase 3: MobX Project State Controller & Incremental Re-parsing — Implementation Plan

**Date:** 2026-08-24
**Status:** Proposed

---

## 1. Overview & Objectives

This document details **Phase 3** of the [Therion Project Parsing, Tree View & Text Editing Roadmap](file:///devel/mapiah/docs/plans/2026-08-24-therion-project-parsing-and-tree-view.md). It builds on the outputs of:

- **Phase 1** — Grammars, parsers, and lossless writers for `thconfig` and `.th` files (`THConfigFileParser`, `THFileParser`, `THConfigFileWriter`, `THFileWriter`).
- **Phase 2** — The recursive project tree loader (`THProjectParser`), the `THProjectNode` model family, `THProjectPathResolver`, and `THProjectParseError`.

Phase 3 introduces the first stateful layer: a MobX `THProjectController` that owns a loaded project, its file/logical tree, dependency graphs, dirty-file tracking, and debounced single-file re-parsing. It is still a non-UI layer — Phase 4 (`THProjectTreeWidget`) and Phase 5 (`THTextEditorWidget`) will observe this controller, but this phase does not build widgets.

### Key Objectives
1. **`THProjectController`**: A MobX store that loads, holds, reloads, and closes a whole Therion project starting from a root `thconfig` or root `.th` file.
2. **Reactive project state**: Observable root node, parse errors, parsing flag, selected node id, cached file contents, and dirty file paths.
3. **Dependency indexes**: Forward and reverse dependency maps, plus a canonical-path → node index, populated from `THProjectLoadResult` and kept coherent across re-parses.
4. **Incremental re-parsing**: Debounced re-parse of a single edited `thconfig`/`.th` file that updates the affected branch without a full project reload whenever possible.
5. **Safe fallback**: Full project reload when a change affects the project root or when incremental splicing is unsafe, while preserving UI identity where the model allows.
6. **Dirty tracking and saving**: Track unsaved text edits and save `thconfig`/`.th` files through the Phase 1 writers; `.th2` canvas saving remains owned by the existing `TH2FileEditController`.

## 3. `THProjectController` Public Surface

```dart
class THProjectController = THProjectControllerBase with _$THProjectController;

abstract class THProjectControllerBase with Store {
  @observable
  String rootConfigPath = '';

  @observable
  THProjectFileNode? projectRootNode;

  @observable
  bool isParsing = false;

  @observable
  ObservableList<THProjectParseError> projectErrors =
      ObservableList<THProjectParseError>();

  @observable
  String? activeSelectedNodeId;

  @observable
  ObservableMap<String, String> fileContentsCache =
      ObservableMap<String, String>();

  @observable
  ObservableSet<String> dirtyFilePaths = ObservableSet<String>();

  @computed
  bool get hasUnsavedChanges => dirtyFilePaths.isNotEmpty;

  @action
  Future<void> openProject(String configFilePath);

  @action
  Future<void> reloadProject();

  @action
  Future<void> reparseFile({
    required String filePath,
    required String updatedContent,
  });

  @action
  Future<void> saveProjectFile(String filePath);

  @action
  Future<void> saveAllModifiedFiles();

  @action
  void selectNode(String nodeId);

  @action
  void closeProject();

  THProjectFileNode? nodeByCanonicalPath(String canonicalPath);

  Set<String> dependenciesOf(String canonicalPath);

  Set<String> dependentsOf(String canonicalPath);

  bool isFileDirty(String canonicalPath);
}
```

### 3.1 State Fields

| Field | Type | Purpose |
| :--- | :--- | :--- |
| `rootConfigPath` | `String` | Canonical root file path; empty when no project is open. |
| `projectRootNode` | `THProjectFileNode?` | Root of the file/logical tree from `THProjectParser.loadProject`. |
| `isParsing` | `bool` | True while initial load, reload, or re-parse work is running. |
| `projectErrors` | `ObservableList<THProjectParseError>` | Project-level diagnostics (missing files, cycles, parse errors). |
| `activeSelectedNodeId` | `String?` | Currently selected tree node id, consumed by Phase 4 navigation. |
| `fileContentsCache` | `ObservableMap<String, String>` | Canonical path → last known text content for `thconfig`/`.th` files. |
| `dirtyFilePaths` | `ObservableSet<String>` | Canonical paths with unsaved text edits. |

Private non-observable indexes are kept as plain maps because the observable tree is the render input:

```dart
final Map<String, Set<String>> _fileDependencies = <String, Set<String>>{};
final Map<String, Set<String>> _reverseDependencies = <String, Set<String>>{};
final Map<String, THProjectFileNode> _nodesByCanonicalPath =
    <String, THProjectFileNode>{};
final Map<String, THProjectNode> _nodesById = <String, THProjectNode>{};
final Map<String, Timer> _reparseTimers = <String, Timer>{};
```

## 4. Loading, Reloading, and Closing

### 4.1 `openProject`

1. Canonicalize `configFilePath` with `p.absolute` and `THProjectPathResolver.canonicalize`.
2. Cancel any pending re-parse timers and call `closeProject()` to clear stale state.
3. Set `rootConfigPath` and `isParsing = true`.
4. Run `THProjectParser.loadProject(rootConfigPath)` inside a `Future`/microtask so the UI remains responsive. For Phase 3, the synchronous parser is acceptable; the call site is isolated so Phase 3.5 or a later optimization can move it to an isolate without changing the controller API.
5. Store the result:
   - `projectRootNode = result.rootNode`.
   - `projectErrors` from `result.projectErrors`.
   - `_fileDependencies` and `_reverseDependencies` from the result.
   - Rebuild `_nodesByCanonicalPath` and `_nodesById` by walking the tree.
6. Clear `fileContentsCache` and `dirtyFilePaths`, then populate the cache for every loaded `thconfig`/`.th` node by reading its file bytes with the same encoding detection used by `THProjectParser`.
7. Set `isParsing = false`.

Errors are never thrown to the caller for recoverable parse/missing-file conditions; those are already represented as `THProjectParseError`. Only unexpected I/O failures are logged through `mpLocator.mpLog` and surfaced as a project error.

### 4.2 `reloadProject`

`reloadProject` is a thin wrapper that re-runs the same full-load path without changing `rootConfigPath`. It is used:

- For explicit “Re-parse project” actions.
- As the safe fallback when incremental splicing is not possible.
- After an external file change is detected outside the text editor.

### 4.3 `closeProject`

1. Cancel all pending `_reparseTimers`.
2. Clear `rootConfigPath`, `projectRootNode`, `projectErrors`, `activeSelectedNodeId`, `fileContentsCache`, `dirtyFilePaths`, and all private indexes.
3. Set `isParsing = false`.

## 5. Indexing & Navigation Helpers

After any full load or branch splice, the controller rebuilds or patches:

- `_nodesByCanonicalPath`: `canonicalPath -> THProjectFileNode`.
- `_nodesById`: `node.id -> THProjectNode`.
- `_fileDependencies`: `file -> included files`.
- `_reverseDependencies`: `included file -> including files`.

`nodeByCanonicalPath`, `dependenciesOf`, and `dependentsOf` expose these indexes without making them observable.

`selectNode(nodeId)` only mutates `activeSelectedNodeId`; it does not open tabs or scroll editors. Those side effects belong to Phase 4/5 and should observe the id change.

## 6. Incremental Re-parsing

### 6.1 Editor Contract

The Phase 5 text editor calls:

```dart
controller.reparseFile(
  filePath: canonicalFilePath,
  updatedContent: currentEditorText,
);
```

The controller is responsible for debouncing, parsing, and updating the tree. The editor does not parse files itself.

### 6.2 Debounce

- A 300 ms timer per canonical file path coalesces rapid keystrokes.
- The timer value lives in `mp_constants.dart` (`mpProjectReparseDebounceMilliseconds = 300`) rather than being inline.
- Calling `reparseFile` again before the timer fires cancels and restarts it.
- `closeProject` and `openProject` cancel all timers.

### 6.3 Local Parse Without Disk I/O

For an already-known file, the controller determines shape from the existing node type:

- `THConfigFileNode` → `THConfigFileParser.parseString`.
- `THDataFileNode` → `THFileParser.parseString`.
- `TH2FileNode` → never re-parsed here; `.th2` canvas edits are owned by `TH2FileEditController`.

For a newly added include, shape is derived the same way `THProjectParser` does:

- Reached from a `thconfig` `source` → data.
- Reached from a `thconfig` `input` → config.
- Reached from a `.th` `input` ending in `.th2` → `.th2` leaf.
- Other `.th` `input` → data.
- Root fallback → basename `thconfig` or a config-only directive → config, otherwise data.

To avoid duplicating Phase 2 logic, Phase 3 includes a small refactor of `THProjectParser` exposing two pure helpers:

```dart
static THProjectFileNode parseFileContent({
  required String canonicalPath,
  required String content,
  required THProjectShape shape,
  required String sourceFilePath,
  required int lineNumber,
});

static THProjectFileNode loadFileNode(
  String filePath, {
  THProjectShape? expectedShape,
});
```

The existing `loadProject` implementation is rewritten to use these helpers, keeping one source of truth for node construction, shape detection, encoding, and logical-node building.

### 6.4 Full-Reload Fallback

Incremental splicing is skipped and `reloadProject()` is used when:

- `projectRootNode` is null.
- `filePath` is the canonical project root.
- `filePath` is not in `_nodesByCanonicalPath`.
- The local parse result changes the file’s type (for example a file that previously parsed as `.th` now has a `thconfig`-only directive, or vice versa).

This conservative rule keeps Phase 3 correctness simple. Performance optimizations beyond it are explicitly deferred.

### 6.5 Include Diff & Splice

For a non-root file, the controller:

1. Parses `updatedContent` into a fresh `THProjectFileNode`.
2. Extracts the local include set from the new node:
   - `THConfigFileNode`: `configFile.sourceFilePaths` and `configFile.inputFilePaths`.
   - `THDataFileNode`: all `THDataInput` elements at any nesting level; `THImport` targets are diagnostics only.
3. Resolves each raw path with `THProjectPathResolver` and canonicalizes it.
4. Compares with the previous local include set stored in `_fileDependencies[canonicalPath]`.
5. For each **removed** include:
   - Find the matching child file node and detach it from its parent.
   - Remove it and its descendants from `_nodesByCanonicalPath`/`_nodesById` unless they are still reachable through another include path.
   - Remove `canonicalPath → childPath` from `_fileDependencies` and `childPath → canonicalPath` from `_reverseDependencies`.
6. For each **added** include:
   - Load or parse the child through `THProjectParser.loadFileNode`.
   - Attach it to the correct parent (the containing `THSurveyNode`, or the file node for top-level/config includes).
   - Record the dependency edge.
7. For each **unchanged** include:
   - Keep the existing child node and its subtree intact.
   - Re-validate only the parent pointer.
8. Replace the edited file’s logical children with the freshly built logical nodes.

### 6.6 Logical-Node & Namespace Update

The newly parsed node contains fresh logical children (`THSurveyNode`, `THCentrelineNode`, `THMapNode`, `THScrapNode`). The controller replaces the old logical children on the edited file node while preserving any child file nodes that did not change.

For `THSurveyNode`s, `fullNamespace` is recomputed leaf-to-root using the ancestor survey ids. Because namespaces are encoded in the id string as well as the field, changed namespaces produce changed ids; Phase 4 must treat an id change as a node replacement, not a move.

### 6.7 Error & Dirty-State Refresh

- The edited node’s `parseErrors` are replaced from the fresh parse, plus any new include/missing-file errors created during the splice.
- `projectErrors` is rebuilt as the union of all node errors and project-level errors, keeping order deterministic (tree order, then include order).
- `dirtyFilePaths` gains the edited canonical path.
- `fileContentsCache[canonicalPath]` is updated to `updatedContent`.

## 7. Saving Files

### 7.1 `saveProjectFile`

For a `thconfig`/`.th` canonical path:

1. Get the content from `fileContentsCache`.
2. Re-read the file’s declared encoding from the cached content using the same header-detection logic as `THProjectParser`.
3. Call `THConfigFileWriter.serializeToBytes` or `THFileWriter.serializeToBytes` with that encoding.
4. Write bytes to disk.
5. Remove the path from `dirtyFilePaths`.
6. If the save changed an include/namespace structure, schedule a debounced re-parse of the saved file to converge the tree.

### 7.2 `.th2` Files

`.th2` files are not written by `THProjectController`. `saveProjectFile`/`saveAllModifiedFiles` detect `.th2` paths and delegate to the existing `TH2FileEditController` save flow through `MPGeneralController`.

### 7.3 `saveAllModifiedFiles`

Iterates over a snapshot of `dirtyFilePaths` and saves each path. If any save fails, the error is logged and surfaced in `projectErrors`, and the path remains dirty.

## 8. Integration with Existing Infrastructure

### 8.1 `MPLocator`

Add a singleton accessor:

```dart
final THProjectController thProjectController = THProjectController();
```

This mirrors the existing eager `mpGeneralController` pattern and makes the controller available without a new service-locator mechanism.

### 8.2 `MPGeneralController`

`MPGeneralController` continues to own tab order and tab controllers. Phase 3 does not modify tab management. It introduces the project controller as a sibling that Phase 4/5 will coordinate:

- Project tree selection requests tab focus through `MPGeneralController`.
- Text editor tabs use `THProjectController.fileContentsCache`.
- Canvas `.th2` edits remain entirely in the existing controller until a later phase synchronizes scrap metadata.

### 8.3 MobX Code Generation

`th_project_controller.dart` contains the MobX source and `part 'th_project_controller.g.dart';`. The generated file is produced by the existing `build_runner` watcher; Phase 3 does not run `build_runner` manually.

## 10. Test Plan

Test numbering continues the Phase 2 block (`t3840`–`t3860`):

| Test file | Coverage |
| :--- | :--- |
| `test/t3870_th_project_controller_test.dart` | open/reload/close lifecycle, observables, node/dependency indexes, selection, dirty state. |
| `test/t3871_th_project_reparse_aux_test.dart` | Pure include-diff, splice, namespace recomputation, and error-merge helpers. |
| `test/t3872_th_project_controller_incremental_reparse_test.dart` | Debounce, full-reload fallback, add/remove include, namespace propagation, cache updates. |
| `test/t3873_th_project_controller_save_test.dart` | `thconfig`/`.th` save encoding/line-ending, dirty clearing, `.th2` delegation. |

Representative scenarios:

1. **Open project**: `openProject(rootConfigPath)` builds the full tree and both dependency maps.
2. **Reload idempotence**: two consecutive `reloadProject()` calls produce an equivalent tree without duplicate file nodes.
3. **Unchanged re-parse**: calling `reparseFile` with unchanged content does not rebuild unchanged child subtrees.
4. **Add include**: editing a `.th` file to add `input passage2.th` attaches a new child and updates reverse dependencies.
5. **Remove include**: removing an `input` detaches the child subtree and its canonical-path indexes.
6. **Rename survey**: changing a survey id propagates `fullNamespace` to descendant surveys.
7. **Edit errors**: malformed content produces node/project errors and keeps previously valid siblings.
8. **Root edit fallback**: editing the root file triggers a full reload rather than a local splice.
9. **Debounce coalescing**: multiple rapid edits produce one re-parse after the configured delay.
10. **Dirty/save round-trip**: edited `thconfig`/`.th` content saves through the Phase 1 writers and clears dirty state.
11. **Missing include**: an added missing include creates a `THMissingFileNode` and an error without aborting the branch update.
12. **`.th2` leaf**: an edited `.th` that references `.th2` preserves the existing `TH2FileNode`; the `.th2` is not parsed.

Fixture files for controller/re-parse tests live under `test/auxiliary/th_project_controller/`, following the existing `test/auxiliary/th_project/` convention.

## 11. Explicit Non-Goals for Phase 3

- No `THProjectTreeWidget`, tree rendering, icons, search, or side-column UI — Phase 4.
- No syntax-highlighting text editor, line-number gutter, or editor shortcuts — Phase 5.
- No canvas/text tab integration or cross-navigation — Phase 6.
- No Therion compiler invocation or log parsing — Phase 7.
- No localization strings, help-page updates, or keyboard-shortcut documentation — Phase 8.
- No isolate-based parsing, file watching, or large-project performance tuning. The controller API leaves room for these, but this phase intentionally uses the existing synchronous `THProjectParser` with debouncing.
- `.th2` canvas contents are not re-parsed by this controller; `.th2` editing and saving stay in `TH2FileEditController`.
